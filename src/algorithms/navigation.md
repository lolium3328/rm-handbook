# 04-b 导航与运动规划（Navigation）

> 本章待完善。

导航方向研究的是：机器人如何确定自身位置、理解周围环境、找到到达目标的路线，并按照规划结果运动。

对于 RM 机器人来说，导航不是简单地寻找一条从起点到终点的路径。一个完整的导航系统通常涉及定位与建图、地图表达、路径规划、轨迹生成和轨迹跟踪等环节。

```text
LiDAR / IMU / 编码器
        ↓
    定位与建图
        ↓
   地图与环境表示
        ↓
     路径规划
        ↓
   轨迹生成与优化
        ↓
     轨迹跟踪
        ↓
      底盘控制
        ↺
```

本方向主要分为三个技术领域：

1. 定位与建图（Localization & Mapping）
2. 路径规划（Path Planning）
3. 轨迹跟踪（Trajectory Tracking）

---

## 1 定位与建图（Localization & Mapping）

**核心问题：机器人如何知道自己在哪里，以及如何理解周围环境？**

机器人通过 LiDAR、IMU、编码器、相机等传感器获取信息，再结合运动模型和环境特征估计自身状态。定位与建图是导航系统的基础。如果机器人无法可靠地确定自身位置，后续规划即使计算出一条合理路线，也可能无法正确执行。

### 1.1 需要建立的基本概念

| 概念 | 需要理解什么 |
| --- | --- |
| Odometry（里程计） | 根据机器人运动和传感器数据估计运动增量 |
| Localization（定位） | 在已有地图或参考环境中估计机器人位置 |
| Mapping（建图） | 根据传感器观测构建环境地图 |
| SLAM | 在地图未知时，同时估计自身位置和构建地图 |
| Sensor Fusion（传感器融合） | 结合不同传感器信息，提高状态估计质量 |
| Scan Matching | 通过匹配不同时刻的点云估计机器人运动 |
| Loop Closure（回环检测） | 识别机器人是否回到曾经经过的位置，并修正累计漂移 |

### 1.2 需要了解的技术

1. 基础状态估计
2. 点云匹配与定位
3. LiDAR Odometry 与 SLAM

### 1.3 建图与地图表达

不同任务不一定需要相同形式的地图。

| 地图类型 | 表达方式 | 主要用途 |
| --- | --- | --- |
| Point Cloud Map | 三维点云 | 环境几何表达、点云定位 |
| Occupancy Grid | 栅格占据状态 | 二维路径规划 |
| Costmap | 栅格代价 | 障碍物避让和局部规划 |
| Voxel Map | 三维体素 | 三维环境表示与碰撞检测 |
| Topological Map | 节点与连接关系 | 大范围路线和区域导航 |

## 2 路径规划（Path Planning）

**核心问题：已知机器人当前位置、目标位置和环境信息，如何找到合理路线，并进一步生成可执行的运动轨迹？**

路径规划不仅要找到一条能够到达目标的路线，还需要考虑障碍物、机器人自身尺寸、运动约束和实际执行能力。

首先区分两个概念：

- **Path（路径）**：描述机器人经过哪些空间位置，通常不包含明确的时间信息。
- **Trajectory（轨迹）**：描述机器人在什么时间到达什么位置，通常还包含速度、加速度等信息。

规划器找到一条绕过障碍物的折线路径，并不意味着机器人可以直接执行。还需要平滑路径、分配速度和时间，并保证运动符合底盘约束。

### 2.1 路径规划的基本问题

需要理解：

- Start：起始位置。
- Goal：目标位置。
- Map：环境地图。
- Obstacle：障碍物。
- Cost Function：路径代价函数。
- Constraints：运动与安全约束。

一个简化的路径规划问题可以表示为：

\\[
\min_{\mathcal P} J(\mathcal P)
\\]

其中，\\(\mathcal P\\) 是规划得到的路径，\\(J\\) 是路径代价函数。代价可以由路径长度、障碍物距离、转弯程度、运动时间等组成。

### 2.2 全局路径规划（Global Planning）

全局规划主要解决：在已知地图或全局环境信息的情况下，如何从起点找到目标位置。

#### 2.2.1 图搜索算法

- Dijkstra
- A*
- D* / D* Lite

| 算法 | 核心思想 | 主要特点 |
| --- | --- | --- |
| Dijkstra | 从起点向外扩展，寻找最短路径 | 不使用目标启发信息 |
| A* | 利用启发函数引导搜索 | 在满足条件时可以保证最优性 |
| D* Lite | 环境变化时进行增量搜索 | 可以复用之前的搜索结果 |

#### 2.2.2 采样式路径规划

不常用，太慢

#### 2.2.3 考虑运动学约束的规划

- Hybrid A*
- State Lattice
- Kinodynamic Planning

普通 A* 在栅格上搜索时，通常只考虑位置邻接关系。但某些机器人不能随意改变朝向或运动方向，因此需要在搜索状态中加入朝向、速度等信息。

例如，Hybrid A* 会在搜索中考虑车辆运动学约束，适合具有非完整运动约束的车辆类机器人。

### 2.3 局部规划与动态避障（Local Planning）

全局规划通常提供整体路线，但机器人实际运动时可能遇到临时障碍物、动态目标、地图变化、定位误差，或者全局路线无法直接执行的情况。

局部规划根据当前状态和局部环境生成短期运动方案，并根据新观测持续更新。

#### 2.3.1 DWA（Dynamic Window Approach）

核心思想：在当前速度附近采样一组可行速度指令，预测机器人执行这些指令后的短期运动，并根据目标方向、速度和障碍物距离进行评价。

#### 2.3.2 TEB（Timed Elastic Band）

核心思想：将局部轨迹表示为带有时间信息的路径点序列，通过优化轨迹点的位置和时间间隔，满足障碍物距离、运动约束和时间要求。

#### 2.3.3 MPC（Model Predictive Control）

核心思想：利用机器人运动模型预测未来一段时间的运动，通过优化控制序列获得当前应该执行的控制量，然后滚动更新。

#### 2.3.4 MPPI（Model Predictive Path Integral）

核心思想：通过采样多组候选控制序列，利用模型预测它们的结果，再根据轨迹代价计算控制序列的加权更新。

需要特别注意：MPC 是一种滚动优化控制框架，MPPI 是一种求解控制优化问题的方法；两者不应简单理解成完全相同层级的算法。

### 2.4 路径如何变成可执行轨迹？

路径搜索得到的结果可能包含折线、尖锐转角和不连续的方向变化。机器人不能总是直接跟踪这些结果，因此需要进一步学习轨迹生成和优化。

#### 2.4.1 基础轨迹生成

- Linear Interpolation
- Trapezoidal Velocity Profile
- LSPB
- Cubic Polynomial
- Quintic Polynomial

#### 2.4.2 样条与轨迹参数化

- Cubic Spline
- B-spline
- Bezier Curve
- MINCO

#### 2.4.3 轨迹优化

轨迹优化不是简单地让路径变得更平滑，而是在轨迹质量、障碍物安全距离、运动约束和执行时间之间寻找平衡。

### 2.5 不同规划方法之间的关系

| 比较 | 需要理解的区别 |
| --- | --- |
| Dijkstra vs A* | 是否利用启发信息引导搜索 |
| A* vs D* Lite | 静态搜索与环境变化下的增量搜索 |
| A* vs RRT | 离散图搜索与连续空间采样 |
| DWA vs TEB | 速度空间采样与带时间轨迹优化 |
| TEB vs MPC | 局部轨迹优化与基于模型的滚动控制 |
| MPC vs MPPI | 优化问题的求解方式 |
| Cubic vs B-spline | 轨迹参数化与连续性特点 |
| 普通样条 vs MINCO | 轨迹表示、约束处理与优化结构 |

不要求新人一开始全部实现，但应该知道这些方法分别解决什么问题，以及它们不能互相简单替代的原因。

## 3 轨迹跟踪（Trajectory Tracking）

**核心问题：规划器已经生成了一条轨迹，机器人如何按照这条轨迹运动？**

即使规划出的轨迹完全合理，如果底盘不能稳定跟踪，机器人仍然可能偏离路线、发生振荡，或者无法在预期时间到达目标。

轨迹跟踪的核心是：根据机器人当前状态与目标路径或轨迹之间的误差，计算下一时刻应该执行的运动指令，并通过反馈不断修正。

### 3.1 需要建立的基本概念

| 概念 | 需要理解什么 |
| --- | --- |
| Path Following | 沿着指定的几何路径运动，不一定严格规定运动时间 |
| Trajectory Tracking | 跟踪带有时间信息的参考轨迹 |
| Tracking Error | 实际状态与期望状态之间的误差 |
| Feedback Control | 根据实际状态反馈修正控制输入 |
| Feedforward Control | 根据期望轨迹提前计算控制输入 |
| Stability | 控制系统是否能够稳定收敛 |
| Control Frequency | 控制器更新频率及其对跟踪效果的影响 |

特别需要理解 Path Following 和 Trajectory Tracking 的区别：

- Path Following：机器人只需要沿着这条路线走，快一点或慢一点都可以。
- Trajectory Tracking：机器人不仅需要经过这些位置，还需要尽可能按照指定时间到达对应位置。

### 3.2 经典轨迹跟踪方法

#### 3.2.1 PID Controller

最基础的反馈控制方法：

\\[
u(t)=K_p e(t)+K_i\int_0^t e(\tau)d\tau+K_d\dot e(t)
\\]

需要理解：

- P、I、D 三个部分的作用；
- 比例、积分和微分对系统响应的影响；
- 稳态误差、超调和振荡；
- 参数整定；
- 积分饱和与抗积分饱和。

PID 是重要的基础方法，不仅用于轨迹跟踪，也广泛应用于电机、速度和位置控制。

#### 3.2.2 MPC Tracking

利用预测模型和滚动优化进行轨迹跟踪。与传统 PID 或 LQR 相比，MPC 可以显式考虑未来一段时间的运动，并将速度、加速度和其他约束加入优化问题。

需要理解：

- 参考轨迹；
- 预测时域；
- 状态和控制输入；
- 跟踪代价；
- 约束优化；
- 滚动时域控制；
- 求解时间与控制频率之间的关系。

MPC 既可以用于轨迹规划，也可以用于轨迹跟踪。两者可能使用相似的优化框架，但目标和输入输出不同。
